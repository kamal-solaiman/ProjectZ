# مخطط قاعدة بيانات ProjectZ

## النطاق

المخطط موجه إلى **SQL Server 2016 SP1 أو أحدث**، بمستوى توافق `130`. هذه الخطوة تنشئ قاعدة الأعمال فقط؛ لا تغيّر كود WPF أو مستودع تسجيل الدخول أو `connectionsettings.json` أو حساب `ProjectZClient` أو صلاحياته.

الجداول لا تحتوي بيانات مبيعات أو مشتريات تجريبية. البيانات المضافة تقتصر على الأدوار الأساسية وإعدادات العملة وإصدار المخطط، مع منح دور Administrator لحساب `admin` إن كان موجودًا دون تعديل كلمة مروره.

## التشغيل

نفّذ من SSMS أو sqlcmd بحساب إداري، بالترتيب:

1. `sql/01_CreateDatabase.sql` للتثبيت الجديد فقط، إن لم تكن القاعدة مجهزة.
2. `sql/02_SeedAdmin.sql` لإنشاء مدير الدخول إن لم يوجد.
3. `sql/06_CreateFullSchema.sql` لإنشاء مخطط الأعمال والعلاقات والفهارس.
4. `sql/07_CreateReportingViews.sql` لإنشاء طرق عرض التقارير.
5. `sql/08_VerifyFullSchema.sql` للتحقق من الأجسام والعلاقات.

السكربتان 06 و07 قابلان لإعادة التشغيل: لا يحذفان جداول أو بيانات، ولا يعيدان إنشاء كائن موجود. عند تطوير عمود لاحقًا يجب إنشاء migration مستقل؛ السكربت لا يبدّل بنية جدول موجود تلقائيًا. `GO` فاصل SSMS/sqlcmd وليس أمر T-SQL يمكن إرساله عبر `SqlCommand` كدفعة واحدة.

## الخريطة والعلاقات

### الأمن والإعدادات

- `Users` هو جدول الدخول الأصلي، ولم يتغير.
- `Roles` و`Permissions` و`UserRoles` و`RolePermissions`: صلاحيات many-to-many دون تكرار الدور لكل مستخدم.
- `SystemSettings`: إعدادات النظام، و`DocumentSequences`: تسلسل مستقل لكل نوع مستند وسنة؛ رقم المستند لا يعتمد على `IDENTITY` لتجنب فجوات الترقيم المعروضة.
- `AuditLog`: سجل إضافي فقط للعمليات الحساسة، ويرتبط بالمستخدم عندما يكون معروفًا.

### العملاء والموردون والكتالوج

- `Customers` و`Suppliers`: بيانات الأطراف الأساسية وحالة النشاط، مع هاتف فريد للعميل عند وجوده.
- `Categories`: شجرة تصنيفات اختيارية، وتمنع التصنيف من أن يكون أبًا لنفسه.
- `Products`: باركود وSKU فريدان عند وجودهما، ثلاث درجات أسعار، تكلفة، حد تنبيه، وخيار تتبع السيريال.

### المخزون والسيريال

- `StockMovements`: دفتر حركات كمية موجب وسالب؛ الرصيد مشتق من مجموعه ولا يُكرر داخل `Products`.
- `InventoryUnits`: سجل مستقل لكل وحدة متتبعة، مع السيريال والتكلفة والمورد والحالة والهالك.
- `PurchaseInvoiceLineUnits` و`SalesInvoiceLineUnits`: تتبع مصدر كل وحدة وبيعها. يظهر سجل البيع حتى بعد المرتجع للحفاظ على التاريخ، و`AllocationStatus` يميز البيع الحالي من المرتجع إلى المخزون؛ فهرس مفلتر يمنع بيع الوحدة مرتين في الوقت نفسه مع السماح بإعادة بيعها لاحقًا.
- `ReturnExchangeUnits`: يربط الوحدات الفعلية بالمرتجع أو الاستبدال.
- `vwProductStock`: يجمع الكميات وحالات الوحدات دون تخزين رصيدين متعارضين.

### المبيعات والمرتجعات

- `SalesInvoices`: رأس الفاتورة وحالتها وخصمها ولقطة بيانات العميل والكاشير.
- `SalesInvoiceLines`: لقطة الصنف والسعر والتكلفة وقت البيع؛ تعديل المنتج لاحقًا لا يغيّر ربح فاتورة قديمة.
- `SalesPayments`: كل تحصيل أو رد في صف مستقل ومرتبط بالحساب المالي؛ يدعم الكاش وفودافون وإنستاباي والدفع المقسّم دون أعمدة ثابتة لكل قناة.
- `ReturnExchanges` و`ReturnExchangeLines`: عملية مرتجع/استبدال وبنودها، مع شرط أن المرتجع يرتبط ببند البيع الأصلي، وأن بند الاستبدال الجديد مستقل.
- `SalesInvoiceActivities`: تاريخ إجراءات الفاتورة.
- `vwSalesInvoiceSummary`: الصافي بعد المرتجع والخصم، التحصيل والرد والمتبقي والتكلفة والربح.

### المشتريات والموردون

- `PurchaseInvoices` و`PurchaseInvoiceLines`: رأس وبنود الشراء ولقطات المورد والصنف والتكلفة.
- `PurchaseReturns` و`PurchaseReturnLines`: مرتجعات مرتبطة بفاتورة وبند الشراء الأصليين.
- `PurchasePayments`: المدفوع للمورد والمسترد منه كحركتين واضحتين، لا كقيمة موجبة غامضة.
- `PurchaseInvoiceActivities`: تاريخ إجراءات الفاتورة.
- `vwPurchaseInvoiceSummary`: صافي الشراء والمدفوع والمسترد والمتبقي للمورد.

### الصيانة

- `MaintenanceOrders`: بيانات الجهاز والعطل والفحص والحالة والفني والتسليم والضمان والتسعير، ولقطة العميل.
- `MaintenanceOrderParts`: قطع من المخزون أو بنود يدوية؛ قيود الجدول تمنع خلط النوعين.
- `MaintenancePayments`: العربون والتحصيل النهائي والرد، مرتبطة بالحساب المالي ومرحلة الدفع.
- `MaintenanceActivities`: تاريخ الحالة والتشخيص والتعديلات.
- `vwMaintenanceOrderSummary`: قيمة القطع والتكلفة والخدمة والعربون والتحصيل النهائي.

### الحسابات والمحافظ

- `FinancialAccounts`: الخزنة وفودافون كاش وإنستاباي وحدود الإيداع والسحب اليومية والشهرية. فهارس مفلترة تفرض خزنة واحدة وحسابًا افتراضيًا واحدًا لكل نوع.
- `CustomerTransfers`: عمليات إيداع/سحب العملاء على المحفظة، والعمولة وصافي النقدي والرصيد بعد العملية وحالة العكس. **لا يوجد رقم مرجعي للتحويل.**
- `FinancialTransactions`: دفتر وارد/منصرف موحد، والرصيد بعد الحركة، ومصدر الحركة، وهل تدخل في حدود المحفظة.
- `TransferGroupId`: يربط طرفي التحويل بين الحسابات دون تخزين مرجع نصي.
- `SourceEntityType` و`SourceEntityId`: رابط تدقيق مرن بمصدر الحركة. لا يُستخدم كعلاقة polymorphic FK زائفة؛ العلاقات التجارية الصريحة موجودة في جداول المدفوعات والعمليات، ويجب على طبقة الكتابة المستقبلية إنشاء المصدر والدفتر في معاملة واحدة.
- `vwFinancialAccountDailyUsage`: استهلاك الحدود اليومية من الحركات المؤهلة فقط.

## قرارات الاتساق

- جميع المبالغ `DECIMAL(19,2)`، والكميات الصحيحة `INT`، والمعرفات التشغيلية الكبيرة `BIGINT`.
- `CHECK` يمنع المبالغ السالبة والكميات غير الصالحة والحالات خارج النطاق وقيم العكس الناقصة.
- المفاتيح الأجنبية تمنع الأيتام. الحذف الافتراضي `NO ACTION` للحفاظ على تاريخ الفواتير والمدفوعات والمخزون؛ الإلغاء أو العكس أو إيقاف النشاط يستخدم بدل حذف التاريخ.
- الأعمدة `RowVersion` في الكيانات المتغيرة تدعم كشف تعارض التعديل المتزامن مستقبلًا.
- الأوقات مخزنة بصيغة `DATETIME2(7)` وبقيمة UTC افتراضية. واجهة العرض تتولى التحويل للتوقيت المحلي عند الربط.
- `AuditLog` وحقول المصدر العامة ليست بديلًا عن العلاقات الأجنبية بين مستندات العمل.
- `PasscodeValueProtected` مخصص لقيمة محمية، وليس تصريحًا بتخزين رمز الجهاز كنص صريح. يجب عند التنفيذ استخدام تشفير مناسب وإدارة مفاتيح خارج قاعدة البيانات، وتقليل ظهوره في السجلات.

## الفهارس والتقارير

الفهارس تغطي البحث بالاسم والباركود والسيريال، وسجل الحساب حسب التاريخ، وعمليات المحفظة والعميل، وفواتير العميل والمورد، وحالات الصيانة والمدفوعات. الفهارس المفلترة تحافظ على uniqueness دون منع القيم غير المسجلة.

طرق العرض لا تعدّل البيانات ولا تستبدل قيود الكتابة. عند ربط التطبيق لاحقًا يجب استخدام معاملات SQL لكل حالة استعمال متعددة الجداول، مع `UPDLOCK/HOLDLOCK` عند تخصيص رقم مستند أو تحديث رصيد، وعدم الاعتماد على قراءة ثم كتابة غير ذرّية.

## التحقق والحدود الحالية

`08_VerifyFullSchema.sql` يعرض الجداول أو طرق العرض الناقصة، ومفاتيح أجنبية معطلة أو غير موثوقة، وأي عمود Reference داخل تحويلات العملاء أو دفترها، وتفاصيل العلاقات. الفحص النصي في CI لا يساوي تشغيل المخطط على SQL Server؛ يلزم تنفيذ السكربتات على نسخة اختبار SQL Server 2016 SP1 ثم اختبار قيود الإدخال والفهارس قبل الاعتماد الإنتاجي.
