# شاشة النسخ الاحتياطي والاسترجاع

## الغرض

شاشة مستقلة ضمن فئة **الإعدادات → النسخ الاحتياطي** تنفّذ عمليتين إداريتين على SQL Server:

1. **BACKUP DATABASE** إلى ملف `.bak` كامل لقاعدة البيانات المضبوطة في `connectionsettings.json` (`ProjectZ` افتراضيًا).
2. **RESTORE DATABASE** من ملف `.bak` موجود، مع استبدال قاعدة البيانات نفسها ببيانات الملف. لا يُكتب اسم القاعدة ثابتًا في الكود؛ يُقرأ من إعداد `Database` ويمرّ بأمان كمعرّف SQL مقتبس.

الشاشة لا تحفظ إعدادات المحل ولا تغيّر المظهر؛ شاشة **اعدادات عامة** مسؤولة عن هوية المحل، وشاشة **المظهر** مستقلة. لكل شاشة مضيف Grid منفصل في `MainWindow.xaml`، واختيار إحداهما لا يعرض الأخرى فوقها.

## مسار الملف: تنبيه أساسي

أوامر `BACKUP` و`RESTORE` تُنفَّذ على **جهاز SQL Server**، والمسار يُقرأ هناك، وليس على جهاز العميل:

- إذا كان SQL Server على نفس الجهاز، فمسار مثل `C:\ProjectZ\Backups\ProjectZ_20261114_1200.bak` يعمل.
- إذا كان SQL Server على جهاز آخر، استخدم مسارًا موجودًا على الخادم أو مشاركة UNC يصل إليها **حساب خدمة SQL Server**، مثل `\\SERVER\Backups\ProjectZ_20261114_1200.bak`.
- زر **استعراض** يختار مجلدًا/ملفًا من جهاز العميل فقط؛ لذلك لا يُعتمد عليه لاكتشاف مسار الخادم. يمكن كتابة المسار مباشرة.
- لا تتحقق الشاشة من وجود المجلد أو الملف محليًا قبل الإرسال؛ SQL Server يعيد الخطأ 3201/3202 إذا تعذّر الوصول إلى المسار، وتعرضه الشاشة برسالة عربية.

## كيف تعمل الشاشة

- **معلومات القاعدة**: تُقرأ من `sys.database_files` (الحجم) و`msdb.dbo.backupset` (آخر نسخة). `backup_start_date` يُعرض بتوقيت جهاز SQL Server كما هو، دون تحويل خاطئ من UTC.
- **اسم الملف**: يبدأ بـ`ProjectZ_yyyyMMdd_HHmmss.bak` ويُعاد توليده تلقائيًا بعد كل نسخة ناجحة، إضافة إلى زر **اسم جديد**، حتى لا تستبدل النسخة التالية ملفًا سابقًا بسبب تكرار الاسم. من يكتب اسمًا موجودًا بنفسه فسيستبدل الملف عمدًا لأن الأمر يستخدم `WITH INIT, FORMAT, CHECKSUM`.
- **الاسترجاع**: يتم من اتصال منفصل إلى `master`، ثم `ALTER DATABASE [<اسم القاعدة من الإعدادات>] SET SINGLE_USER WITH ROLLBACK IMMEDIATE`، ثم `RESTORE ... WITH REPLACE, RECOVERY`. في `finally` تُعاد القاعدة إلى `MULTI_USER` من نفس اتصال `master` حتى لو فشل الاسترجاع. الاتصال بالقاعدة المستهدفة أثناء الاستعادة كان يبقيها مشغولة ويمنع العملية.
- **بعد الاسترجاع**: تُعاد قراءة معلومات القاعدة وتُفرّغ خانة المسار. يجب تحديث بقية الشاشات أو إعادة تشغيل البرنامج؛ الجلسات الأخرى كانت قد قُطعت أثناء `SINGLE_USER`. إذا كان اسم القاعدة في `connectionsettings.json` غير `ProjectZ`، فالاسترجاع يستهدف الاسم المضبوط نفسه.
- **قائمة الملفات**: تُقرأ محليًا من جهاز العميل للعرض فقط. إذا كان مجلد الخادم غير متاح من الجهاز، ستكون القائمة فارغة، وهذا لا يعني أن النسخ غير موجودة؛ استخدم المسار الكامل في بطاقة الاسترجاع.
- **قفل النموذج**: أثناء النسخ أو الاسترجاع تُعطَّل الحقول والأزرار (`IsBusy`/`IsIdle`) لمنع عمليتين متداخلتين.

## الصلاحيات المطلوبة على SQL Server

حساب الاتصال `ProjectZClient` يحتاج صلاحيات أعلى من القراءة/الكتابة العادية. شغّل السكربت الجاهز من SSMS **بحساب sysadmin** على خادم SQL Server:

```sql
:r sql/18_EnableBackupRestore.sql
```

أو افتح `sql/18_EnableBackupRestore.sql` ونفّذه كاملًا. السكربت idempotent، ويتحقق من وجود القاعدة واللوجن أولًا، ثم يضيف فقط ما ينقص:

- `ALTER ROLE [db_owner] ADD MEMBER [ProjectZClient];` داخل قاعدة بيانات المشروع — يسمح بـ`BACKUP DATABASE` و`ALTER DATABASE … SINGLE_USER/MULTI_USER`.
- `ALTER SERVER ROLE [dbcreator] ADD MEMBER [ProjectZClient];` — يسمح بـ`RESTORE DATABASE` لأنه يحتاج `CREATE DATABASE` على مستوى الخادم.

بدون هذين الدورين يظهر في الشاشة خطأ 262/229 بالرسالة العربية التي تسمّي `sql/18_EnableBackupRestore.sql`. إذا كان اسم القاعدة أو اسم تسجيل الدخول مختلفًا في `connectionsettings.json`، استبدل `ProjectZ` و`ProjectZClient` في السكربت بما يطابق الإعداد. هذه صلاحيات واسعة؛ استخدم حساب نسخ احتياطي مخصصًا إن كانت سياسة المؤسسة لا تسمح بمنحها لحساب التطبيق العام.

بعد تنفيذ السكربت **أغلق البرنامج وأعد فتحه** إن كانت المحاولة الفاشلة قد حدثت بالفعل، لأن صلاحيات SQL Server تُقرأ عند فتح الاتصال. الكود يفرّغ connection pool بعد خطأ الصلاحية، لكن إعادة التشغيل تضمن محاولة نظيفة.

## الاستخدام

1. سجّل الدخول بحساب متصل بقاعدة البيانات؛ تظهر شارة «متصل بقاعدة البيانات».
2. من **الإعدادات → النسخ الاحتياطي**.
3. **نسخة**: اكتب مسار المجلد على جهاز SQL Server، وراجع اسم `.bak` أو اضغط **اسم جديد**، ثم **أخذ النسخة الاحتياطية**.
4. **استرجاع**: اكتب مسار `.bak` على جهاز SQL Server أو اختره من استعراض الجهاز المحلي إن كان الخادم هو نفس الجهاز، ثم اضغط زر الاسترجاع وأكّد التحذير.
5. راقب شريط الحالة للنتيجة؛ يبقى ظاهرًا أسفل الشاشة خارج منطقة التمرير.

## ملاحظات القبول

- تحقق من إنشاء ملف `.bak` فعليًا على الخادم، ومن ظهوره في قائمة الملفات إذا كان المجلد متاحًا للعميل.
- أعد تشغيل التطبيق بعد تغيير اسم المحل أو استرجاع قاعدة، وتأكد من عمل الدخول.
- الاسترجاع عملية مدمّرة: اختبرها على قاعدة تجريبية أولًا.
- لم يُشغّل WPF أو SQL Server داخل بيئة الفحص النصي؛ يلزم Windows مع SQL Server 2016 SP1 أو أحدث.
