# سجل القبول — لا يزال مفتوحًا

**الحالة: غير مكتمل الاعتماد اليدوي.** بيئة العمل المحلية Linux بلا SQL Server 2016 SP1 أو WPF، لكن Windows CI بنى نسخة EXE ورفع artifact وشغّل اختبار حفظ المشتريات على SQL Server LocalDB معزول. يجب أن يسجل المنفذ التاريخ والأجهزة والإصدار الفعلي والنتيجة والدليل، دون أسرار، قبل اعتماد التسليم على بيئة المحل.

## فحوص البيئة الحالية

- مراجعة المصدر: يستخدم اتصال SqlClient مباشر وparameterized SELECT، ولا يوجد وسيط أو ORM.
- مراجعة SQL نصيًا: CREATE DATABASE/ALTER DATABASE وCREATE TABLE وIF وSYSUTCDATETIME وtransaction/locks جميعها من صياغة SQL 2016 أو أقدم. المستوى 130 محدد صراحة. ليست هذه شهادة تنفيذ فعلي.
- فحوص آلية محلية موثقة في `STATIC-CHECKS.txt`: JSON وXML وhash السكربت وتطابقه مع صيغة PBKDF2 وعدد الجداول المنشأة.
- اختبار C# الأمني لم يُشغّل في البيئة المحلية؛ لا SDK. تشغيله في Windows CI ناجح.
- بناء Windows ونشر artifact ناجحان في CI.

## إصلاح شاشة المظهر البيضاء — تحقق آلي منفذ

بلغ المستخدم أن فتح «الاعدادات ← المظهر» يعرض صفحة بيضاء فارغة. السبب: `MainViewModel.SelectItem` كان يرسل إشعار `PropertyChanged` لكل رايات الشاشات إلا `IsAppearanceSelected`، فتختفي الرسالة التوضيحية بينما تبقى حاوية شاشة المظهر `Collapsed`.

[Windows CI run 43635925470](https://github.com/kamal-solaiman/ProjectZ/actions/runs/43635925470) على Commit `b74e84c` (2026-11-14): نجح `build` و`purchase-sql` بعد الإصلاح.

- أُضيف الإشعار الناقص، وأصبح اختبار WPF الدخاني ينشئ `MainViewModel` حقيقيًا ويتنقّل فعليًا إلى «المظهر» ويتحقق أن الحاوية صارت `Visible` وأن الشاشة قِيست بأبعاد حقيقية (لا لوحة بيضاء فارغة).
- حارس انحدار في الفحوص الثابتة: كل راية `Is…Selected` في `MainViewModel` يجب أن يُرسل لها إشعار داخل `SelectItem`؛ حُذف السطر مؤقتًا للتأكد أن الفحص يسقط فعلًا ثم أُعيد.
- الحد: هذا تحقق آلي على Windows CI وليس جلوسًا أمام البرنامج؛ إعادة التجربة اليدوية على جهاز المحل ضمن الاختبار 29 ما زالت مطلوبة.

## إصلاح ألوان النصوص العامة — تحقق آلي منفذ

بلغ المستخدم أن ألوان النصوص «لا تتغير أبدًا» عند تبديل المظاهر، وأن التصميم المخصص لا يتحكم في بعض النصوص مثل القائمة الجانبية. أضاف الفرع أولًا حارس WPF يقيس اللون الفعلي للنص؛ فشل الحارس على Windows CI قبل الإصلاح في `PosRtlTextStyle` رغم أن قيم الموارد تتغير، مما أثبت أن فرش الإرث القديمة (`DynamicResource Color` داخل `Freezable`) لا تتبع استبدال اللون reliably.

الإصلاح: يستبدل `ThemeManager` كل فرشاة `Theme.Legacy.*` وفرش POS ومفتاح `Accent` على مستوى التطبيق بالفرشاة الحية للدور؛ وأضيفت أربعة أدوار نصوص مستقلة في المخصص (العناوين، القائمة الجانبية، الثانوي للقائمة، الأزرار) مع فحص تباين لكل مجموعة، وهجرة تلقائية لملفات الإصدار 1. القائمة الجانبية تستخدم الآن `NavigationInk`/`NavigationMuted` صراحة، والعناوين تستخدم `Heading`.

- [Windows CI run 43644591672](https://github.com/kamal-solaiman/ProjectZ/actions/runs/43644591672) على Commit `937d63a` (2026-11-14): فشل متوقع لحارس النص قبل الإصلاح (`FAIL: PosRtlTextStyle effective Foreground changes between themes`)، ونجح `purchase-sql`.
- [Windows CI run 43645868469](https://github.com/kamal-solaiman/ProjectZ/actions/runs/43645868469) على Commit `84ada71` (2026-11-14): نجح `build` و`purchase-sql` بعد الإصلاح، بما في ذلك حارس `TextColorTests` الذي يقيس اللون الفعلي للنص والعنوان والزر والقائمة الجانبية وأسماء الإرث، واختبارات الاستقلالية والهجرة والتباين.
- الحد: تحقق آلي على Windows CI وليس قبولًا بصريًا يدويًا؛ الاختبارات 35–37 أدناه مطلوبة على جهاز المحل.
