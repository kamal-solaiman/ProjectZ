# ProjectZ — تسجيل الدخول والخروج

مشروع C# / WPF يستهدف **.NET 10 LTS**، باتصال مباشر إلى **SQL Server 2016 SP1 Express (13.0.4001.0)**، ومستوى توافق **130**. لا توجد API أو ORM أو قواعد محلية أو وظائف إضافية.

## حالة التسليم — غير مكتمل الاعتماد

تم إعداد المصدر والسكربتات وإعدادات النشر والأدلة. بناء Windows CI ينتج EXE ويرفع artifact، واختبارات SQL تتحقق من حفظ وتسوية المشتريات على LocalDB معزول. **لم يُشغّل WPF يدويًا في هذه الجلسة، ولم يُختبر SQL Server 2016 SP1 على أجهزة LAN الفعلية.** بيئة العمل المحلية Linux بلا .NET SDK أو SQL Server؛ اختبارات .NET وSQL تُنفذ في Windows CI. لا يعد المشروع مكتمل الاعتماد حتى تنفيذ [سجل القبول](docs/ACCEPTANCE.md) على البيئة المطلوبة.

## شاشة الاعدادات العامة واسم البرنامج

«اعدادات عامة» تحفظ بيانات المحل (الاسم، وصف مختصر، العنوان، الهواتف، البريد، اسم قسم الصيانة) والإعدادات العامة (رمز العملة وكودها، حد التنبيه الافتراضي للمخزون، عبارة أسفل الفاتورة) في `dbo.SystemSettings`. **اسم المحل هو اسم البرنامج**: يُحفظ في المفتاح `StoreName` ويظهر فورًا في عنوان النافذة الرئيسية، شريط القائمة الجانبية، شاشة تسجيل الدخول، عناوين كل نوافذ الإضافة والتعديل، رؤوس فواتير البيع والشراء وإيصالات الصيانة، وعبارة الترحيب — دون إعادة تشغيل. اسم الملف التنفيذي `ProjectZ.exe` لا يتغير. المظهر والنسخ الاحتياطي في شاشتين مستقلتين ولا تُداران من هذه الشاشة. التفاصيل في [الاعدادات العامة](docs/GENERAL_SETTINGS.md).

## استوديو المظهر

من «الاعدادات ← المظهر» يمكن اختيار ثمانية أنظمة بصرية أو تصميم لوحة مخصصة من ثمانية أدوار لونية مع منتقي RGB/HEX وعتامة وانحناءات وفحص تباين. الاختيار يُعاين مباشرة على البرنامج كله؛ «حفظ المظهر» يثبته في `%LOCALAPPDATA%\ProjectZ\appearance.json` لكل جهاز/مستخدم Windows، ويُحمّل قبل شاشة الدخول حتى دون اتصال SQL. المطبوعات الورقية معزولة عن المظهر. التفاصيل وحدود التنفيذ البصري في [استوديو المظهر](docs/THEMES.md).

## شاشة المستخدمين

«المستخدمين» تدير **حسابات الدخول** إلى البرنامج من جدول `dbo.Users` نفسه: إضافة حساب باسم دخول وكلمة مرور، تعديل الاسم الظاهر واسم الدخول وحالة التفعيل، تعيين كلمة مرور جديدة، تعطيل/تنشيط، وحذف الحساب غير المرتبط بأي سجل. كلمة المرور لا تُرسل إلى SQL؛ يُحفظ hash PBKDF2‑HMAC‑SHA256 (600,000 دورة) فقط. الشاشة لا تنفذ أدوارًا أو صلاحيات في هذه المرحلة، وعنصر «الصلاحيات» ما زال للتحديد فقط. التفاصيل في [شاشة المستخدمين](docs/USERS.md).

## قائمتا التقارير والمصروفات

أضيفت فئتان جديدتان إلى الشريط الجانبي: «التقارير» (تحت «العملاء والموردين» وفوق «المستخدمين») بعناصرها الستة: تقارير المبيعات، تقارير المشتريات، تقارير الصيانة، تقارير المالية، تقارير المصروفات، اجمالي التقارير؛ و«المصروفات» (تحت «التقارير» وفوق «المستخدمين») بعناصرها الثلاثة: اضافة مصروف، فواتير المصروفات، تصنيفات المصروفات. **تقارير المبيعات والمشتريات والصيانة والمالية وشاشات المصروفات الثلاث منفّذة**؛ يبقى «تقارير المصروفات» و«اجمالي التقارير» للتحديد فقط. القائمتان تتبعان نظام المظهر الحالي تلقائيًا وتظهران كأيقونتين في الشريط المطوي. التفاصيل في [قائمتا التقارير والمصروفات](docs/REPORTS_EXPENSES.md) و[شاشة تصنيفات المصروفات](docs/EXPENSE_CATEGORIES.md).

## شاشة تصنيفات المصروفات

من «المصروفات ← تصنيفات المصروفات» تُدار أقسام المصروفات (إيجار، فواتير، مرتبات، مواصلات، صيانة، أخرى) في جدول `dbo.ExpenseCategories`: إضافة باسم ووصف اختياري، تعديل الاسم والوصف داخل الصف، وحذف بتأكيد. كل كتابة داخل معاملة `Serializable` مع سطر في `dbo.AuditLog` بالوحدة `ExpenseCategories`، والاسم فريد بلا حساسية لحالة الأحرف. الحذف يُرفض برسالة عربية إذا ارتبط التصنيف بمصروفات لاحقًا. الشاشة تعمل داخل مساحة العمل وتتبع المظهر الحالي. نفّذ `sql/19_EnableExpenseCategories.sql` مرة واحدة على قاعدة قائمة. التفاصيل في [شاشة تصنيفات المصروفات](docs/EXPENSE_CATEGORIES.md).

من «المصروفات ← اضافة مصروف» تُسجَّل المصروفات الفردية: تصنيف من `dbo.ExpenseCategories`، ومبلغ إجمالي، وتاريخ (اليوم افتراضيًا)، وبيان اختياري، و**وسيلة دفع واحدة أو أكثر** بجانب التصنيف؛ كل وسيلة حساب مالي نشط ومبلغ، ويجب أن يساوي مجموعها مبلغ المصروف. عند الانتقال من وسيلة إلى وسيلتين يُقسَّم المبلغ مناصفةً مبدئيًا، ويُرفض الحفظ قبل توزيع كامل المبلغ. الحفظ داخل معاملة `Serializable` يكتب سطرًا في `dbo.Expenses` برقم `EXP-YYYY-0000` من `dbo.DocumentSequences`، وسطرًا لكل وسيلة في `dbo.ExpensePayments`، وينقص رصيد كل حساب، ويكتب حركة خارجة في سجل كل حساب و`CreateExpense` في `dbo.AuditLog`. الملخص وآخر مصروف محفوظ في الجهة المقابلة لبيانات المصروف. الشاشة نموذج إدخال فقط، وقائمة المصروفات الكاملة تُعرض في «فواتير المصروفات». نفّذ `sql/20_EnableExpenses.sql` ثم `sql/21_EnableExpenseSplitPayments.sql` مرة واحدة على قاعدة قائمة. التفاصيل في [شاشة اضافة مصروف](docs/EXPENSES.md).

من «المصروفات ← فواتير المصروفات» تُعرض كل المصروفات المحفوظة في سجل واحد يقرأ `dbo.Expenses` و`dbo.ExpensePayments` و`dbo.ExpenseCategories` و`dbo.Users` و`dbo.FinancialAccounts`: رقم المصروف وتاريخه وتصنيفه وبيانه ومبلغه وتوزيعه على الحسابات ومن سجّله. الشاشة للقراءة فقط لا تكتب أي صف ولا تغيّر أي رصيد، وتحتوي فلاتر فترة (اليوم/آخر 7 أيام/هذا الشهر/الشهر الماضي/فترة مخصصة)، وبحثًا نصيًا في الرقم والبيان والتصنيف والمستخدم والحساب، وفلاتر تصنيف وحساب ومستخدم ووسائل دفع ونطاق مبلغ وترتيب، وبطاقات ملخص (العدد والإجمالي والمتوسط والمقسم وأكبر تصنيف)، وتصدير CSV وطباعة ونافذة تفاصيل لكل مصروف. تتحدث تلقائيًا بعد أي حفظ في «اضافة مصروف» أو تعديل في «تصنيفات المصروفات». لا تحتاج سكربتًا جديدًا بعد `sql/20` و`sql/21`. التفاصيل في [شاشة فواتير المصروفات](docs/EXPENSE_INVOICES.md).

## إغلاق التطبيق وعملية Windows

يضبط التطبيق `ShutdownMode="OnLastWindowClose"` ويتتبع النوافذ المفتوحة، فينهي WPF عند إغلاق آخر نافذة. أثناء تسجيل الدخول أو الخروج، تُعرض النافذة البديلة قبل إغلاق الحالية. تُلغى محاولات الدخول الجارية عند الإغلاق، ولا يُسمح لنتيجة SQL متأخرة بفتح نافذة جديدة بعد إغلاق نافذة الدخول. للتحقق على Windows، أغلق بـ X أو Alt+F4 قبل الدخول وبعده وبعد تسجيل الخروج، وتأكد من اختفاء `ProjectZ.exe` من Task Manager؛ راجع الاختبارين 16 و17 في [سجل القبول](docs/ACCEPTANCE.md). لم يُشغّل WPF فعليًا في بيئة العمل الحالية.

## واجهة ProjectZ العربية

اسم التطبيق وملف التشغيل `ProjectZ.exe` واسم قاعدة البيانات `ProjectZ`. إذا كانت لديك قاعدة قديمة باسم `FitohPhone`، خذ نسخة احتياطية وأغلق الاتصالات ثم شغّل `sql/05_RenameLegacyDatabaseToProjectZ.sql`؛ لا تشغّل إعداد قاعدة جديدة فوق قاعدة قديمة لم تُرحّل.

الواجهة باللغة العربية وباتجاه RTL (`ar-EG`). شريط عنوان Windows يبقى LTR حتى تظهر أزرار التصغير والتكبير والإغلاق على اليمين، بينما محتوى النوافذ RTL. يبقى إدخال اسم المستخدم وكلمة المرور LTR لأنهما مُعرّفان. بعد تسجيل الدخول تظهر قائمة جانبية قابلة للتمرير بفئات المبيعات والمشتريات والصيانة والمالية والعملاء والموردين والتقارير والمصروفات والمستخدمين والإعدادات. الشاشات المنفذة تُفتح من عناصرها؛ وما لم يُنفَّذ بعد (مثل «الصلاحيات») يعرض مساحة العمل توضيحًا بذلك بدل ادعاء تنفيذه؛ أما «المظهر» فمربوط بشاشة استوديو المظهر الفعلية.

## بناء ونشر من Windows

```powershell
dotnet run --project tests/ProjectZ.Security.Tests -c Release
pwsh tests/ProjectZ.Purchase.Sql.Tests/Run.ps1
dotnet build ProjectZ.sln -c Release
dotnet publish src/ProjectZ/ProjectZ.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PublishTrimmed=false -o publish/win-x64
```

النتيجة المتوقعة بعد نجاح الأمر: `publish/win-x64/ProjectZ.exe` و`connectionsettings.json`. انسخ **محتويات مجلد النشر بالكامل**. ملف الإعدادات مقصود أن يبقى منفصلًا. يمكن أيضًا استخدام ملف تعريف FolderProfile من Visual Studio. من GitHub Actions بعد دفع الفرع وتشغيل workflow، نزّل artifact باسم `ProjectZ-win-x64`. عند التحديث احتفظ بملف `connectionsettings.json` المضبوط للعميل ولا تستبدله بإعدادات خادم آخر.

Microsoft.Data.SqlClient مثبت على **6.1.3** (خط 6.1 LTS ويدعم SQL Server 2016؛ تأكيد اتصال SP1 الفعلي ما زال مطلوبًا). النقل يستخدم SqlConnection وSqlCommand وSqlDataReader وSqlParameter؛ اسم المستخدم parameter من نوع NVARCHAR(100). PBKDF2-HMAC-SHA256 بعدد 600,000 دورة، salt عشوائي 16 بايت، ناتج 32 بايت، ومقارنة ثابتة الزمن. لا تُرسل كلمة مرور مستخدم التطبيق إلى SQL؛ يُجلب hash ويُفحص محليًا. حساب SQL للاتصال مختلف عن حساب التطبيق admin.

لا تحفظ كلمة مرور المستخدم في ViewModel؛ تُقرأ PasswordBox عند الضغط وتُمسح فورًا. كأي API يعتمد string، لا يمكن ضمان محو نسخة كلمة المرور فورًا من ذاكرة CLR. الجلسة بالذاكرة فقط، وتُزال عند الخروج، ولا يتم حفظ بيانات دخول أو إظهار تفاصيل SqlException للمستخدم.
